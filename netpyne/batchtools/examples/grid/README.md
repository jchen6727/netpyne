# Grid Search Example

This example demonstrates a parameter grid search using `batchtk`'s `Trial` API, running trials concurrently via `ThreadPoolExecutor`.

## Files

| File | Description |
|------|-------------|
| `grid.py` | Main script — builds the grid and runs trials |
| `rosenbrock.py` | Worker script executed by each trial |
| `script.toml` | Defines the shell submission template |
| `output/` | Directory where trial outputs are written |

---

## How It Works

### 1. Constructors — Dispatcher & Submit

```python
from netpyne.batchtools.search import generate_constructors
dispatcher, _ = generate_constructors('sh', 'sfs')
```
```


`generate_constructors(job_type, comm_type)` returns a `(dispatcher_constructor, submit_constructor)` pair.

| Argument | Value | Meaning |
|----------|-------|---------|
| `job_type` | `'sh'` | Runs jobs as local shell scripts |
| `comm_type` | `'sfs'` | Communicates via shared filesystem (no sockets) |

This resolves to `(LocalDispatcher, SHSubmitSFS)` — suitable for running locally without a cluster scheduler.

---

### 2. The TOML Template

If the autogenerated shell template provided by SHSubmitSFS does not work, you can use a .toml file to customize your script.

`script.toml` defines how each trial's shell script is generated:

```toml
command_template = "sh {output_path}.sh"

script_template = """\
#!/bin/bash

{handles}
{env}

cd {project_dir}
python rosenbrock.py
"""
```

the command_template is what is the call to the interpreter that executes the shell script.
formats to `sh output/rosenbrock_0.sh`, `sh output/rosenbrock_1.sh`, etc. for each trial,

but for HPC clusters, you can use `sbatch`/ `qsub` or any scheduler command instead of `sh`.

the script_template formats to the actual shell script that is executed for each trial, with placeholders for environment variables and project directory.

| Placeholder | Description |
|-------------|-------------|
| `{handles}` | Environment variable exports injected by the dispatcher (passes `x0`, `x1`, `label`, etc. to the worker) |
| `{env}` | Additional environment setup |
| `{project_dir}` | Absolute path to the working directory |

`TomlParser` reads this file and `parser.get_submit_class()` returns a submit class whose instances render the `script_template` for each trial. The placeholders are filled in at submission time:

The rendered `.sh` file is written to `output/` and executed via the `command_template`.

### 3. Parameter Grid

```python
params = {
    'x0': [0, 1],
    'x1': [2, 4],

```


`itertools.product` computes the full Cartesian product, producing all combinations:

```
(x0=0, x1=2), (x0=0, x1=4), (x0=1, x1=2), (x0=1, x1=4)
```

### 4. The `Trial` API

```python
from batchtk.algos import Trial

trial = Trial()
trial.set_fixed_trial_args(
    dispatcher_constructor=dispatcher,
    project_dir=project_dir,
    output_dir=output_dir,
    submit_constructor=submit,
    storage_dir=storage_dir,
    submit_kwargs={'command': 'python rosenbrock.py'},
    interval=5,
    storage_constructor=constructors.SQLiteStorage,
    log_constructor=constructors.BatchtkLogger,
    check_storage=True,
)
```


`set_fixed_trial_args` stores shared configuration so that `trial.run_trial(label, tid, config)` only needs the per-trial arguments. Each call:

1. Renders the submission script using the TOML template, injecting `config` values as environment variables via `{handles}`.
2. Executes the script.
3. Polls the shared filesystem every `interval` seconds until the worker writes its result.
4. Stores the result in the SQLite database at `storage_dir`.

---

### 5. Concurrent Execution

```python
with ThreadPoolExecutor(max_workers=4) as executor:
    all_results = list(executor.map(run_trial, enumerate(grid)))
```


Up to **4 trials run concurrently**. Each thread independently submits its script and waits for the result. Because communication is filesystem-based (`sfs`), there are no socket conflicts between threads.

---

### 6. The Worker Script (`rosenbrock.py`)

`cfg.update()` populates `cfg` from the environment variables injected by the dispatcher. `sim.send(results)` writes the result dictionary back to the shared filesystem for the waiting dispatcher to collect.

## Running

```shell script
cd netpyne/batchtools/examples/grid
python grid.py
```


Results are stored in `output/rosenbrock.sqlite.db` and printed to stdout.
